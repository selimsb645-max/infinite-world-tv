# INFINITE WORLD TV

An original 3D hybrid runner/racer game that plays itself, rendered as video and broadcast
24/7 on YouTube Live. No copyrighted characters, vehicles, music or environments: every
asset is generated by this repository's own pipeline.

**Status: planning. No implementation code yet** — this repository currently holds the
analysis, architecture and roadmap that the build will follow.

## The one design decision everything else follows from

A live-rendered 3D game cannot be streamed from a free host: software GL at 1080p on a free
VM is single-digit FPS, and GitHub Actions cannot hold a process open for a month.

So the system is **rendered ahead of time and streamed from a buffer**:

```
Godot Movie Maker (deterministic frames)  ->  FFmpeg (encode)  ->  segment queue
                                                                      |
                                              FFmpeg loop -> YouTube RTMP (tiny CPU)
```

Rendering happens in batches on CI or a workstation. The always-on part is only the loop
streamer, which needs a fraction of one core. That is what makes zero-cost 24/7 realistic.

## Repository layout (target)

```
game/            Godot 4 project (GDScript)
  core/          GameManager, WorldManager, DifficultyManager
  generation/    LevelGenerator, AntiRepetitionManager, GameValidator
  entities/      CharacterController, VehicleController, AutonomousPlayer
  assets/        AssetManager, registries
  ui/            broadcast overlays (score, world name, banner)
tools/           Python: blender_assets/, render_batch.py, encode.py, qc.py
broadcast/       stream_loop.py, health.py, recovery.py
dashboard/       FastAPI app + templates (RBAC, HMAC session)
docs/            this documentation set
tests/           unit + property tests (generation, validation, similarity)
.github/         CI: tests, level-uniqueness soak, render job
```

## License and originality

All assets are produced inside this repository (Blender scripts, procedural audio synthesis,
CC0-only textures). No third-party game assets are imported. A per-asset provenance record is
required before any asset enters the build — see docs/ARCHITECTURE.md section 6.
