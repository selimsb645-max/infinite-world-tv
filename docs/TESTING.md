## How to run it yourself

```bash
# 1. Godot 4.3 (no GPU needed; the headless build is enough)
curl -sSL -o godot.zip https://github.com/godotengine/godot/releases/download/4.3-stable/Godot_v4.3-stable_linux.x86_64.zip
python3 -c "import zipfile; zipfile.ZipFile('godot.zip').extractall('.')"
chmod +x Godot_v4.3-stable_linux.x86_64

# 2. Import once (creates .godot/)
cd game && ../Godot_v4.3-stable_linux.x86_64 --headless --path . --import

# 3. Run the suite
../Godot_v4.3-stable_linux.x86_64 --headless --path . --script res://tests/test_runner.gd
```

CI runs the same three commands (`.github/workflows/game-tests.yml`), so a green run here and a
green run there mean the same thing.

### Bugs this suite actually caught

1. **Vehicle spawned off the ground.** Level 1's `vehicle_spawn` was z=+90 while the ground
   platform ended at z=+50, so the car fell into the void and every vehicle check failed. Fixed
   by extending the ground behind the spawn and moving all vehicle spawns onto the track.
2. **Mode switch teleported the player.** Switching used the level's spawn point, so the player
   jumped backwards mid-run. Fixed: the swap now carries the current position across.
3. **The test itself was wrong.** The first version counted frames as if 60 frames were one
   second. In headless script mode the loop runs faster than real time, so 45 frames measured
   only 0.3s of acceleration and looked like a broken vehicle. The suite is now time-based on
   accumulated delta.

## Known limitations (honest list)

- The character and vehicle are built from primitives in code. There are no Blender-authored
  meshes yet; that is Phase 03. "Original cartoon character" currently means "original
  geometry, generated by this repo", not "finished art".
- The vehicle is a `CharacterBody3D` arcade model, not `VehicleBody3D`. Chosen for determinism
  (Phase 03 pre-rendering needs identical runs from identical inputs). No tyre physics.
- Animations are procedural (scale squash for the slide, camera lerp). No AnimationTree, no
  skeletal animation.
- Audio is a few generated tones. No music, no mixing bus, no loudness target yet.
- Rendering was not visually inspected in this environment: the sandbox has no display and no
  GPU, so the checks are state-based, not pixel-based. Visual QA needs a run on a machine with
  a screen, and that is the first item for the owner to look at.
- 60 FPS was not measured. The headless renderer cannot measure it.
